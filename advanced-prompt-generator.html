person ROLE & CONTEXT 
You are a senior UX/UI designer specializing in e-commerce payment systems with deep expertise in cognitive load reduction. Your task is to redesign a mobile-first checkout payment interface that currently suffers from decision paralysis and high abandonment rates.

CONTEXT:
- Platform: Mobile e-commerce app (iOS/Android)
- Current Problem: 70% cart abandonment at payment step
- Root Cause: 12 payment options shown simultaneously, cognitive overload
- Target Users: Mobile shoppers aged 25-45, varying tech literacy
- Business Goal: Increase conversion rate by 40%
analytics PROBLEM ANALYSIS 
COGNITIVE LOAD ISSUES IDENTIFIED:
1. **Choice Overload**: 12 payment options exceed Hick's Law optimal range (3-4 choices)
2. **Visual Hierarchy**: Equal visual weight prevents attention guidance
3. **Touch Target Issues**: Mobile touch targets below 44px minimum
4. **Context Blindness**: No adaptation based on user history or purchase amount
5. **Memory Burden**: Users must remember and compare option details

SPECIFIC IMPROVEMENTS NEEDED:
- Reduce visible choices from 12 to 3-4 primary options
- Implement smart defaults based on user history
- Add progressive disclosure for secondary options
- Increase touch target sizes for mobile
- Add visual hierarchy to guide attention
rule DESIGN CONSTRAINTS

block MUST RESPECT 

- Mobile-first responsive design (320px minimum width)
- Touch targets minimum 44px × 44px
- WCAG 2.1 AA accessibility compliance
- Support for iOS 14+ and Android 8+
- Maintain brand colors and typography
- Load time under 2 seconds on 3G
- Support for 10+ payment methods (but show 3-4 primarily)
- Integration with existing payment gateway APIs
- Biometric authentication support where available

speed PERFORMANCE TARGETS 

- Decision time: Reduce from 45s to under 15s
- Form completion: Increase from 30% to 70%
- Error rate: Decrease by 60%
- User satisfaction: Improve to 4.5/5.0
- Conversion rate: Increase by 40%
design_services REQUIRED DESIGN PATTERNS

check_circle IMPLEMENT THESE PATTERNS 

1. **PROGRESSIVE DISCLOSURE PAYMENT SELECTOR**
   - Primary section: Show 3-4 most common payment methods
   - Secondary section: "More payment options" accordion/dropdown
   - Smart defaults: Auto-select user's last successful method
   - Visual hierarchy: Primary options 2x larger than secondary

2. **CONTEXT-AWARE ADAPTATION**
   - Purchase amount < $50: Show fewer options (simplicity focus)
   - Purchase amount > $500: Show more options (flexibility focus)
   - Return users: Highlight previously used methods
   - New users: Show most popular options first

3. **MOBILE-OPTIMIZED INTERACTION**
   - Bottom sheet for payment selection (thumb-friendly)
   - Swipe gestures to reveal more options
   - Haptic feedback on selection
   - One-tap payment for saved methods

4. **TRUST & CONFIDENCE BUILDERS**
   - Payment method security badges
   - Processing time indicators
   - Fee transparency (if applicable)
   - Help tooltips for complex options
warning ANTI-PATTERNS TO AVOID

dangerous DO NOT IMPLEMENT 

❌ **CHOICE PARALYSIS**
   - Never show all 12+ payment options simultaneously
   - Avoid equal visual weight for all options
   - Don't use generic "Payment Method" dropdown without hierarchy

❌ **MOBILE USABILITY ISSUES**
   - No touch targets smaller than 44px
   - Don't require pinch-to-zoom for readability
   - Avoid hover-only interactions
   - Don't place critical actions in hard-to-reach areas

❌ **COGNITIVE OVERLOAD**
   - Don't require users to remember information from previous steps
   - Avoid complex fee structures without clear explanation
   - Don't hide critical information behind multiple clicks
   - Avoid using industry jargon without explanation

❌ **TRUST DESTROYERS**
   - Don't hide security information
   - Avoid unexpected costs revealed at final step
   - Don't use vague error messages
   - Avoid breaking established payment flow patterns
