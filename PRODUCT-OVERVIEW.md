# Cognitive Load Intervention Engine - Product Overview

## 🎯 Product Vision

**Decision-support and prompt-generation tool** that transforms UX problems into actionable AI-ready design instructions through cognitive and behavioral principles.

## 🔄 Core Product Logic

```
Problem + Context → Matched Principles → Practical Actions → Structured Prompts
```

### User Journey
1. **Problem Definition**: User describes UX challenge (form abandonment, alert fatigue, etc.)
2. **Context Selection**: User specifies decision environment (data entry, navigation, etc.)
3. **Principle Matching**: System identifies relevant cognitive/behavioral principles
4. **Action Translation**: Principles converted into practical UX/UI recommendations
5. **Prompt Generation**: Structured prompts created for specific AI design tools
6. **Implementation**: User copies prompt into Figma Make, Windsurf, ChatGPT, or Claude

## 🎨 Product Architecture

### Input Layer
- **Natural Language Problem Description**: Users describe their UX challenge
- **Context Selection**: Decision environments (Data Entry, Decisions, Navigation, etc.)
- **Sector Specification**: Industry/workflow context (Commercial, Laboratory, etc.)
- **Tool Selection**: Target AI design tool (Figma, Windsurf, ChatGPT, Claude)

### Intelligence Layer
- **Problem Classification**: AI maps description to taxonomy
- **Principle Matching**: Database lookup with relevance scoring
- **Context Adaptation**: Tailors recommendations to specific environments
- **Tool Optimization**: Customizes output for each AI platform

### Output Layer
- **Matched Principles**: Relevant cognitive/behavioral principles with explanations
- **Practical Actions**: Specific UX/UI implementation guidance
- **Structured Prompts**: Tool-specific, ready-to-use instructions
- **Anti-Patterns**: Explicit guidance on what to avoid

## 🧠 Supported Problem Types

### Common UX Challenges
- **Form Abandonment**: Users starting but not completing forms
- **Alert Fatigue**: Too many notifications causing important ones to be missed
- **Poor Findability**: Users unable to locate information or features
- **Information Overload**: Too much data presented at once
- **Decision Fatigue**: Inability to make decisions due to complexity
- **Trust Issues**: Users lacking confidence in system or information
- **Error Rate**: High frequency of user mistakes or system errors
- **Navigation Complexity**: Difficult wayfinding and information architecture

### Decision Environments (Contexts)
- **Data Entry & Forms**: Input validation, form completion, manual data capture
- **Decision & Approvals**: Risk assessment, validation, authorization workflows
- **Navigation & Search**: Finding information, wayfinding, discovery patterns
- **Monitoring & Alerts**: Dashboards, notifications, anomaly detection
- **Collaboration & Handover**: Team workflows, knowledge transfer, coordination

## 📋 Generated Prompt Structure

Every prompt follows this rigorous 7-section format:

### 1. Design Goal
- Clear objective statement
- Success metrics
- Business impact

### 2. UX Problem to Solve
- Specific problem definition
- Root cause analysis
- User impact assessment

### 3. Recommended Patterns
- Exact design patterns to implement
- Specific interaction details
- Visual hierarchy specifications

### 4. Constraints
- Technical limitations
- Platform requirements
- Performance targets
- Brand/compliance requirements

### 5. Anti-Patterns to Avoid
- Explicit "do not" instructions
- Common mistakes to prevent
- Alternative approaches

### 6. Expected Tone/Structure
- Interface personality guidelines
- Interaction tone specifications
- Structural requirements

### 7. Validation Criteria
- Measurable success metrics
- Quality standards
- Testing requirements

## 🎯 Example Transformation

### User Input
"Users are abandoning our e-commerce checkout due to too many payment options"

### System Output
```
MATCHED PRINCIPLES:
- Hick's Law (95% match): Decision time increases with choice quantity
- Progressive Disclosure (88% match): Complex information revealed incrementally
- Recognition over Recall (82% match): Leverage familiar patterns

WHY THEY APPLY:
- Hick's Law directly addresses choice overload in payment selection
- Progressive Disclosure reduces perceived complexity
- Recognition over recall uses familiar payment method patterns

PRACTICAL ACTIONS:
- Limit primary payment options to 3-4 choices
- Group secondary options under "More" accordion
- Use visual cards with trust indicators
- Implement smart defaults based on user history

GENERATED PROMPT (Figma Make):
[Complete structured prompt with exact specifications]
```
